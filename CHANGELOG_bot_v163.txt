bot_v163_audit_hardening

Стабилизация поверх bot_v162_start_hard_fix.

Основные изменения:
- /start вынесен в отдельную приоритетную очередь start-ui и больше не ждёт обычную длинную операцию того же чата.
- Безопасные UI callback (Назад, Назад в осн. окно, INFO, закрытие/возвраты служебных окон) идут по ключу конкретного chat_id + message_id в отдельной window-ui очереди.
- Финансовые и неизвестные callback по-прежнему последовательны по чату.
- При выполнении безопасной навигации убран общий chat-wide lock; используется lock конкретного окна. Для финансовых операций общий chat lock сохранён.
- callback receipt ACK запускается через 0.15 с.
- BOT TOKEN удалён из webhook URL. Новый путь: /tg/<secret>.
- Добавлена поддержка заголовка X-Telegram-Bot-Api-Secret-Token, если версия pyTelegramBotAPI поддерживает secret_token.
- remove_webhook + 0.5 с больше не выполняется на каждом старте. Старое поведение только при WEBHOOK_FORCE_RESET=1.
- Restore принимает bot_v163_*.

Правки из ТЗ окон:
- Ф111: текущий день помечается 📅 и имеет приоритет над меткой расхода 📝.
- Ф113/Ф114: текущий день также помечается 📅.
- В календарь выбора конца периода добавлена кнопка «⏹ До конца текущего дня» с переходом сразу к выбору формата.
- Ф52/Ф53: список чатов строится из объединённого tenant-scoped реестра: tenant chat ids + data chats + known_chats + forward_rules.
- Ф233: файловая задача считается успешной только если Telegram реально подтвердил send_document. Добавлены безопасные transient-повторы отправки и явная ошибка, если документ не отправлен.

Сохранены исправления v160-v162:
- Ф232 отключён для обычных операций, Ф233 оставлен для файлов.
- параллельные окна, /iz-mr, /tz, маркеры/токены окон;
- навигационная история коммитится только после успешного edit;
- /start всегда создаёт видимое новое Ф91.
