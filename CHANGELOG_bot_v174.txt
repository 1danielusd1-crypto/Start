bot_v174_simplified_task_dispatcher

ЦЕЛЬ
Упростить «📋 Диспетчер задач» до понятной работы прямо внутри рабочего Telegram-чата и исправить список чатов владельца.

ИСПРАВЛЕНО
1. Панель владельца больше не использует tenant-scoped collect_all_known_chat_ids(), из-за которого показывались только несколько чатов текущего пространства и мог появляться «Чат 0».
2. Чаты диспетчера берутся из реестра кругов v164 отдельно:
   - 1️⃣ Первый круг;
   - 2️⃣ Второй круг.
   Нулевой chat_id, приватный owner chat и удалённые боты/чаты отфильтровываются.
3. Основное меню задач рабочего чата упрощено до основных действий и счётчиков.
4. Карточка задачи/покупки упрощена: главные статусы сразу кнопками, изменение и история — отдельно.
5. Добавлен автоматический подхват обычных сообщений по редактируемым ключевым словам.
6. По умолчанию распознаются категории:
   - задача;
   - покупка;
   - выполнено;
   - отложено;
   - отмена;
   - в работу.
7. Ключевые слова настраиваются отдельно для каждого рабочего чата через «⚙️ Ключевые слова».
8. Автоподхват можно включать/выключать отдельно в каждом чате.
9. Статусные ключевые слова безопасны:
   - действуют ответом на исходное сообщение или карточку задачи;
   - либо с явным номером, например «#17 готово».
   Слово «готово» без привязки не закрывает случайную задачу.
10. Добавлен статус ❌ Отменена. Покупку также можно ⏸ отложить.
11. Старые задачи/UID/история v172 сохранены, миграция данных не требуется.
12. Старые кнопки v172 «admin/list/open/history» перенаправляются в упрощённый интерфейс v174, чтобы старые сообщения не возвращали пользователя в сложное меню.
13. Текст, вводимый в старый v172 prompt, не может случайно автосоздать вторую задачу.
14. Restore validator принимает snapshots v174.

ХРАНЕНИЕ
Используются существующие v172 root maps:
_tasks_v172
_task_settings_v172
_task_source_index_v172

То есть UID, история и SQLite + MEGA delta-сохранение сохраняются.
