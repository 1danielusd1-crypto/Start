bot_v145_memory_guard_streaming_forensics

1. Добавлен адаптивный Memory Guard для Render 512 MB:
   - пороги warning/high/critical/emergency;
   - GC + malloc_trim(0);
   - безопасная выгрузка cold fields только когда бизнес-очереди свободны;
   - тяжёлые пользовательские экспорты временно не запускаются при опасной RAM;
   - финансовые, forwarding и delta-задачи не удаляются и не блокируются.

2. Диагностика теперь различает:
   - RAM основного Python-процесса;
   - RAM всего cgroup/контейнера;
   - пиковую RAM контейнера;
   - cgroup memory.events/OOM-счётчики;
   - дочерние процессы MEGAcmd/ffmpeg;
   - загруженные cold fields, очереди, кэши, journal/window trace;
   - память до/после Excel, MEGA, ffmpeg и других тяжёлых операций.

3. В максимальный журнал добавлен раздел MEMORY FORENSICS.

4. XLSX sheet XML теперь записывается потоково во временный файл, без сборки всего листа в одной большой строке RAM.

5. Секретные медиа и файлы восстановления скачиваются из Telegram потоково на диск.

6. ffmpeg:
   - stderr больше не копится в RAM;
   - при критической памяти сжатие пропускается, используется безопасный fallback;
   - добавлены замеры памяти до/после процесса.

7. Снижены стандартные worker/pending-лимиты для Render 0.15 CPU; порядок финансов и пересылки сохранён.
   Старые Render Environment overrides продолжают действовать и теперь видны в журнале.

8. Стек новых потоков по умолчанию ограничен 2 MB (BOT_THREAD_STACK_KB).

9. KeyedTaskPool после выполнения немедленно освобождает ссылки на Telegram update/media payload.

10. DelayedTaskScheduler автоматически удаляет устаревшие отменённые записи из heap.

11. Диагностика окон адаптивно уменьшает только RAM-хвост при высокой памяти; полные события остаются в durable-журнале MEGA.

12. Автоматический аварийный restart реализован, но по умолчанию выключен (MEMORY_SAFE_RESTART_ENABLED=0).
